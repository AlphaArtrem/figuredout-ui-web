Read me first

Five mechanics, borrowed and adapted.

Nothing in src/, styles/ or stories/ was touched. This folder is a standalone static page: it copies the package's tokens verbatim, adds callpool's mechanics on top, and shows each one beside what the package renders today so the two are comparable against Storybook. Every borrowed rule is tagged — CP callpool, FO figuredout, MIX merged.

  • 01

    Tokens mostly stay put

    The mechanics only add: four decorative glow hues, a measure, a gutter, and a seam colour. The one place existing values do move is the light theme — see mechanic 06, where that is the entire point.

  • 02

    Product voice wins

    callpool's uppercase-mono buttons and 2px radius are marketing choices. The hybrid keeps figuredout's buttons, radii and focus rings — and takes callpool's structure, scale and motion.

  • 03

    Every number is mono

    Both systems already agree here. The hybrid promotes it from a per-component decision to a named type role, so tables and dialogs get tabular figures for free.

Mechanic 01 CP

The hero that never lands on its own words.

The package has no hero at all, so this is a straight lift. Two columns on a laptop — art with a figures card riding up over its bottom quarter, words beside it. Under 880px the art and the words share one grid cell: the art hangs from the top at a capped width, the copy is dropped below the raised arm by an offset computed from the image's own aspect ratio, and the bottom fifth of the picture is masked out so its straight cut does not read as a rule across the page. Resize the frame and watch the copy stay clear.

The frame is a real viewport; the media queries answer to it.

The overlap is a negative margin, not absolute positioning

margin-top: -25% on the card. A percentage margin resolves against the container's width, and the art is 890×900 — so a quarter of the width is a quarter of the height. The card still occupies its grid row, so the header grows to contain it instead of the card escaping onto the section below.

Source order is the phone's reading order

Art, card, words in the markup; grid-template-areas puts them back into the laptop's arrangement. No order, so the tab sequence never disagrees with the screen.

The numbers are sized by their row, not the viewport

clamp(1.1rem, 8.5cqi, 2rem) with container-type: inline-size on the row. A long figure shrinks to fit the card instead of overflowing it — the same trick the wall cells below use.

Mechanic 02 MIX

Section heads, at a scale you can navigate by.

Section variant="plain" already has the good bones: an icon chip and a mono eyebrow in a 10rem rail, heading and description in the column beside it, a divider above. All the hybrid changes is the scale — the h2 goes fluid from 1.875rem up to 3.25rem, and the description becomes a real lede. Every head on this page is the hybrid one.

Mechanic 03 MIX

Cards in a line read as one object.

callpool draws the hairline between cards as a 1px gap over a seam-coloured ground instead of giving each card its own border: no doubled lines where two cards meet, no page showing through the gap. The adaptation is the corners — at a 1rem radius the corner cells have to carry the rounding themselves, because clipping the frame would slice the hover shadow. Hover a cell in either pane.

Cell counts are chosen so every breakpoint divides evenly

Four cells go 4 → 2 → 1, never 3. A hole in a grid of hairlines reads as a missing figure, which is exactly the wrong thing for a wall of numbers to imply.

The hover is a surface change, not a lift

callpool lifts a seam cell 2px and covers the sliver of seam ground with the shadow. At a 1rem radius that sliver shows at the corners, so the hybrid swaps the translate for surface-raised + --shadow-hover + z-index: 1. Standalone cards — the ledger, the tiles — still lift.

Figures are sized by the cell

clamp(1.25rem, 10.5cqi, 2.75rem). Set from the longest string the slot actually holds; a narrower cell gets smaller digits rather than a second line.

Mechanic 04 MIX

An open tile is an overlay that stayed where it was.

The package's ExpandableTile keeps the same surface when it opens, so a long page of open tiles flattens into one wall of text. The hybrid gives the open state the elevation the system already reserves for dialogs — --shadow-overlay, surface-raised, the strong ring, a 3px lift, and a body that fades in from above. No new token. Open a tile in each pane.

Why <details> instead of a button? Open by default, so the popped state is visible

Space and Enter, find-in-page opening the right tile, and printing an expanded page all come from the browser. The package's controlled API (open / onOpenChange) maps onto <details> without losing any of that.

Something the mockup turned up: light mode has no raised surface

--color-surface and --color-surface-raised are both #ffffff in the light theme, so the open tile's surface change does nothing there and the whole popped state rests on the shadow. Dark mode has a real step (#18191b → #212225). Either the light theme wants a tinted raised surface, or the elevation story is shadow-only in light and should say so.

Mechanic 05 CP

Faded hue dots, all the way down.

Twenty radial gradients on a layer behind the content — body::before at z-index: -1, so there is nothing in the hit test and no stacking context to reason about. They scroll with the page, so a reader meets a different circle every screen or so, and each has an explicit rem size so the circles stay circular however long the document gets. Each dot is a named custom property, which is what makes the density control in the top bar possible: many, some, few and off compose subsets of the same twenty, so the dots never move — there are simply fewer of them. You are looking at it right now.

Density — many / some / few / off — is in the top bar.

The glow palette is not the semantic palette

Four decorative tokens — --glow-1…4 — kept separate on purpose. A status colour changing must never re-tint the wallpaper. They are also lighter and more saturated than their semantic cousins, because figuredout's light-mode hues are dark enough that a 10% wash reads as a grey smudge.

Every stop is far below full opacity

Three named stops, and each theme sets its own: light needs roughly double, because at 10% over a tinted near-white ground a circle is invisible — which is exactly what happened the first time. The dots that pass behind text are always the faintest of the three. Text contrast is untouched in both themes.

Sections arrive in reading order

The scroll reveal is gated behind @supports (animation-timeline: view()), with a one-shot on-load fallback. Without the gate a browser with no view timeline keeps the first keyframe's opacity: 0 and hides the page outright. prefers-reduced-motion stops all of it.

Mechanic 06 MIX

White is the top of the ladder, not the surface.

Today the page is #fafafa and both the card and the raised card are #ffffff — a 2% step, then none at all. Every card depends on its hairline to exist, and "raised" is not a state the light theme can express. Dark mode has no such problem: #111113 → #18191b → #212225 is three real steps. The fix is to stop spending white on the resting surface and reserve it for what is lifted — page ground drops to a tinted neutral, the card sits just under white, white means raised.

The ladder is what makes the rest of the page work

Apply one and switch to light: the seam grid's hover, the popped tile and the hero ledger all start reading in light mode, because surface-raised finally means something. None of those components change — only the four values under them.

Shadows carry the ground's hue, not black

Each palette re-tints --shadow-raised / -hover / -overlay with its own neutral — rgba(16, 32, 22, …) for sage. A pure-black shadow on a tinted ground greys out the colour beneath it and reads as dirt; a hue-matched one reads as depth. It also lets the shadows come down in opacity, because they no longer have to fight a white surface to be seen.

Text contrast, honestly

Against each palette's own surface: fg-muted clears 9:1 and fg-subtle clears 6.5:1 in all three, so both are AA for body text with headroom. Today's theme is higher still — 11.4:1 and 8.6:1 — because it is measured against pure white. That is the trade: a little contrast headroom back, in exchange for surfaces that can be told apart without a border.

Sage is the recommendation, and it is the conservative one

Its neutrals lean the same way callpool's light theme does (#f7f8f7 / #eceeec / #dde1dd), it agrees with the brand green rather than sitting neutral against it, and it is close enough to today's greys that nothing in the product suddenly looks like a different application. Paper is the one with an opinion; slate is the one nobody will notice.

The one open question

The display face. Sentence-case product sans is the default here because it is figuredout's voice, but the condensed-caps cut is what makes callpool look like callpool — toggle it in the top bar and decide. If you want it, it needs a real webfont, not font-stretch: condensed against a system fallback, which resolves differently on every machine.

The light theme is the only real regression risk

Everything else is additive or opt-in, so Storybook baselines hold. Re-valuing the light surfaces changes every light-mode snapshot in the package at once — which is the point, but it means the palette wants to land as its own commit, with the visual review done in one pass rather than mixed into a component change.

The art is a placeholder

hero-art.png is callpool's mascot, copied in unchanged. It is here because the hero's numbers — the -25% overlap and the 64% copy offset — are derived from its 890×900 shape. Swap in a 1:1 asset of your own and they still hold; a different aspect ratio means recomputing both.
